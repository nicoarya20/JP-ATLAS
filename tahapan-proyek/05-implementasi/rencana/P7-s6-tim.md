## 1. Ringkasan
- Menu **Tim** (`/app/team`, hanya baca) menampilkan orang yang berbagi proyek dengan pengguna, beban aktif/terlambat per orang, dan detail orang. Aturan privasi **D10**: angka beban hanya untuk Admin (semua), Pengelola proyek (hanya tugas di proyek yang ia kelola), dan diri sendiri. **Angka orang lain tidak pernah masuk respons API** untuk yang tidak berhak: penyaringan terjadi di WHERE SQL (bukan post-filter, bukan CSS) dan dibuktikan tes kontrak per peran yang memindai JSON.
- **Tim ≤ 4 kueri per halaman**, tak bergantung jumlah orang; dijaga `tests/support/query-count.ts` (sudah ada).
- Dibedakan tegas dari `/dashboard/users` (Admin, akun dan peran, sudah ada): Tim memakai **peran di proyek**, tidak mengubah apa pun; `/dashboard/users` memakai **peran akun**.
- A7: **pra-cek hapus akun** menolak penghapusan bila akun itu satu-satunya Pengelola proyek (kini tidak ada pra-cek; FK `CASCADE` diam-diam membuat proyek tanpa pengelola). A8: kolom pengingat acara bawaan, **bersyarat** pada S7 Events (tanpa Events tidak ada yang diatur).
- **10 tugas (M01-M10)**, ≈ **13,75 hari-orang AI** (M09 bersyarat 1,5 → inti ≈ 12,25) + reviewer ≈ 3-4. R10 memberi 5-8 hari untuk seluruh S6 bagian Tim+hapus akun; angka ini di atas R08 (Tim 3-5 + 1-2) karena memuat tes privasi per peran, tes jumlah kueri, perubahan berkas bersama, dan UI mobile/skala teks.
- **Keputusan konservatif**: kolom **ketersediaan (Tersedia/Sedang rapat) TIDAK dibuat di S6** karena bergantung pada tabel Events (S7, belum ada) dan R10 menurunkannya ke Could; dapat ditambahkan nanti tanpa mengubah kontrak (field baru bersifat aditif).
- Tiga pertanyaan terpenting (bagian 10): Q1 filter "Orang" di Semua Tugas vs D10; Q2 siapa yang ditolak hapus akun (tunggal di proyek yang di Sampah juga?); Q3 A8 ditunda sampai S7?

## 5. Data & API
**Skema:** tidak ada tabel baru (R08 §3.2). Satu migrasi kecil usulan **M05**: `CREATE INDEX IF NOT EXISTS project_member_project_id_role_idx ON project_member (project_id, role)` (menjawab "siapa pengelola proyek X" untuk Q2 dan pra-cek A7). **Nomor: diusulkan, bukan diklaim** (pemegang baton; terakhir `0016_task_core.sql`). M09 (bersyarat) menambah kolom nullable `app_setting.event_default_reminders` di migrasi lain. Dua DB: dev dan `DATABASE_URL_TEST`.

**Endpoint** (modul `server/api/app-team.ts` ≤150 baris, `.use(appContext)`, didaftarkan di `app.ts`; **setelah** `teamPickerApi` agar `/picker` tidak tertangkap `/:userId`, dijaga `tests/app-route-precedence.test.ts`):
| Metode · Path | Respons | Izin |
|---|---|---|
| `GET /api/app/team?projectId&q&sort=name\|overdue&limit&offset` | `{ summary: {people, projects, active?, overdue?}, people: [{ id, name, jobTitle, image, isSelf, projects: [{id,name,role}], load?: {active, overdue, alsoElsewhere?} }], total }` | Semua role login. `sort=overdue` oleh yang tak berhak → `422 SORT_NOT_ALLOWED` (bukan diabaikan diam-diam; UI tak menawarkannya) |
| `GET /api/app/team/:userId` | `{ person: {id,name,jobTitle,department,email,phone?}, projects: [...], tasks?: [{number,title,status,dueDate,projectId}] (maks 20), tasksVisible, load?, alsoElsewhere? }` | Admin: siapa pun disetujui; lainnya: diri sendiri atau berbagi proyek; selain itu `404 NOT_FOUND` |
Kunci `load`, `tasks`, `alsoElsewhere`, `summary.active/overdue` **tidak ada (undefined, bukan `null`/0)** bila pemanggil tak berhak; `phone` hanya diri sendiri/Admin. Galat memakai bentuk seragam `{error,code,status,requestId}`, pesan Indonesia.

**Aturan visibilitas (D10, M01)** `canSeeLoad(viewer, targetId, viewerMemberships)` → himpunan `projectId` yang boleh dihitung:
| Pemanggil | Untuk orang lain | Untuk dirinya |
|---|---|---|
| Admin / super-admin | semua proyek hidup | semua |
| Pengelola (`manager`; termasuk Member yang ditunjuk Pengelola, K1) | hanya proyek yang ia kelola; `alsoElsewhere=true` bila orang itu punya tugas aktif di proyek lain (tanpa rincian) | semua tugasnya |
| Member / Pemantau / PM bukan-pengelola | **tidak ada** | semua tugasnya |
Impersonasi (Q9) hanya baca, tidak dibatasi tambahan. Super-admin sama dengan Admin.

**Kueri (maks 4, di luar kueri sesi/aktor yang dihitung terpisah)** — `server/team/team.query.ts`, `team.load.query.ts`:
1. Orang berhalaman (`limit` 50, bawaan 24; offset, tim kecil): Admin → akun disetujui dan tidak ter-ban (`accountActive`, diekspor dari `picker.query.ts` ke `server/team/account-active.ts`); lainnya → `DISTINCT user_id` dari `project_member` pada proyek hidup yang saya ikuti (`project_member_user_id_idx` + PK) JOIN `user` + `profile`; filter `projectId`/`q` (LIKE dengan `likeText`); `count(*) OVER()` untuk `total`.
2. Peran per proyek untuk `pageIds` **dan** peran saya di proyek itu: satu kueri `project_member JOIN project` (proyek tidak di Sampah).
3. Beban: dari kueri 2 diturunkan di memori `loadScope[userId] = set proyek yang boleh`; kueri ini **hanya** meminta `assignee_id IN (pageIds yang punya scope)` dan `project_id IN scope-nya` (parameter `unnest(userIds[], projectIds[])`): `count(*) FILTER (due_date < $today)` untuk terlambat, `bool_or(project_id NOT IN scope)` untuk `alsoElsewhere`. `$today = isoDateIn(now, METRICS.TIME_ZONE)` dikirim string ISO. Orang tanpa tugas → `{active:0,overdue:0}` (dibuat di memori, bukan hilang). Tugas di proyek Sampah tidak dihitung; tugas di proyek `on_hold/completed/canceled` dihitung (R03 Q10, ASUMSI sampai dijawab).
4. Ringkasan (`summary`): satu agregat untuk orang/proyek (+ tugas aktif/terlambat hanya untuk Admin/Pengelola atas proyek yang mereka kelola).
Detail: ≤ 3 kueri (orang+profil, proyek bersama, tugas bila berhak).

**Scope & kontrak:** `/api/app/team*` GET → `app:read` (sudah otomatis); tambahkan assertion di `tests/api-keys/scopes.test.ts` dan `scopes.pm.test.ts` (GET diizinkan untuk key `app:read`). `PM_KEY_DENY` tidak berubah (tak ada rute destruktif). **Kontrak:** menambah URL `/api/app/team` dan `/api/app/team/:userId` serta entri NAV "Tim" adalah **aditif**; sesuai `docs/decisions/0002-contract-v1.md` tetap butuh baris baru di `tests/contract-v1.test.ts` (daftar rute/NAV/ekspor) dan catatan Permintaan Perubahan Kontrak (M10). Berkas guard/izin bersama (`server/access/*`, `server/auth.ts`, `server/guard.ts`, `server/permissions.ts`, migrasi) = disetujui user satu per satu (KEPUTUSAN §6).
